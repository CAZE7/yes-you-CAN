> - 1.46: **Der Weg von einem realen Fahrzeug zu Daten ist gebaut — als Beobachtung, nicht als Wissen (ADR 0058).** Ausgangspunkt war die Anfrage, „das Auto komplett auszulesen und als ODX zu speichern"; drei Annahmen darin sind vor dem Code geprüft worden: (a) **ein Auto enthält kein ODX** — ODX (ISO 22901-1 / ASAM ODX 2.2) ist ein Austauschformat für *Beschreibungen*, aus einem Fahrzeug lesbar sind Antworten, also wird ODX *aus den Antworten geschrieben*; > - 1.43: **Haskell-Konformanz ist ein Release-Gate, der Diagnose-Loop ist produktionsreif, Provenance+Replay ist beschlossen (ADR 0055/0056/0057).** (1) **Das Differential läuft in jedem CI-Lauf** (ADR 0055): neu `tests/architecture/haskell-conformance-gate.test.ts` (Projekt `architecture`, derselbe Träger-Mechanismus wie `coverage-gate.test.ts`): das Kind ist `npm run formal:conform -- --compare` — Gate und Kommando können nicht auseinanderlaufen (eine Abfrage auf den Skripttext bemerkt es, wenn das Skript nicht mehr auf die CLI zeigt). Grün ist nur, wenn **beide** Sätze (28 iso15765-2, 44 write-safety) die Zeile `TS ⇄ Haskell differential clean (N vectors)` tragen (gematcht, nicht nur Exit-Code geprüft); Exit 1 fällt mit dem Bericht des CLI (Vektor, Input, beide Ergebnisse, Differenzpfade); **Exit 2 fällt in der CI** — „a release without the differential is not a release\": ein Runner, auf dem der Vergleich nicht laufen kann, darf kein Release schneiden, das Konformität für ISO-TP und Write-Safety behauptet. Die CI ist die Maschine, auf der die Toolchain garantiert ist (GitHub-Runner ubuntu-24.04 liefern GHC 9.14.1 vorinstalliert, gemessen an der `actions/runner-images`-Doku); lokal gilt die gleiche Disziplin nur, wo sie tragbar ist — ohne Toolchain ein **sichtbarer Skip** (`skipIf(!isCi && !hasHaskell)` + `::notice`-Modus-Annotation), nie ein unsichtbares Grün; `retry: 0`, Timeout 10 min. Die CLI kompiliert jetzt `ghc` einmal in ein tmp-Verzeichnis (je ein Lauf pro Satz) statt pro Satz den ganzen formale Baum zu interpretieren; `runhaskell`/`runghc` bleiben für Interpreter-only-Maschinen. Gemessen in dieser Umgebung: `CI=true` ohne Toolchain → harter Fehlschlag (by design), lokal → sichtbarer Skip. **Ehrlich:** GHC ist in dieser Arbeitsumgebung nicht installierbar (gemessen: apt/deb-Mirror, downloads.haskell.org, Hackage, Nix-Channels, Conda-Hosts, GitHub-Release-Assets — alle blockiert), also findet die **erste echte Messung der Haskell-Seite im ersten CI-Lauf** statt; ist er rot, hat das Gate seinen Job getan, die Abweichung steht in der Log-Zeile benannt. (2) **Der Diagnose-Loop ist eine Zustandsmaschine mit maschinenlesbarem Diff** (ADR 0056): jede Hypothese trägt jetzt ihre Evidenz **mit Seite** — Pflichtfelder `Hypothesis.supporting`/`against` (`{itemId, why}`, die Seiten entscheidet `citationsOf` an der einen Stelle in `hypotheses.ts`: proven DTC → für, unproven DTC → gegen („no loaded definition documents this code"), proven Pattern → für, Signal-Items nach Check-Verdict, neutrale Checks zitierlos; jedes Zitat existenzgeprüft gegen den Set). Der empfohlene Test ist der mit dem höchsten `value = owner.confidence + 0.1 × |{ h′ ≠ owner : h′.checks teilt das Signal }|` über **alle** ungetesteten Checks — die alte Heuristik „erster offener Check der führenden Hypothese" ist weg: eine Messung, die drei Hypothesen entscheidet, schlägt eine, die eine entscheidet (die Spec pinnt den Fall, in dem die führende Hypothese damit *verliert*); Tie-Break `windowMs` → Owner-Rang → Check-Ordnung, `DiscriminatingTest.uncertaintyReduction` trägt den Wert, die Rationale endet mit der Zahl selbst. `GuidedDiagnosisState.evidenceIds` (Pflicht) ist die Menge, über die ein Schritt diffed wird; `advanceGuidedDiagnosis(before, afterInput)` liefert `DiagnosisStep { before, after, changes }` (outcome inkl. `absent`, confidence bei Δ > 1e-9, evidence added/removed) — gleiche Welt rein, gleiche Welt raus: **leeres Diff**.
